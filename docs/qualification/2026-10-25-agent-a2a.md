# Agent A2A qualification — 2026-10-25

This records the standing of `story:agent-a2a` (the A2A listener of `b10x-loom agent serve`) at
its implementation, before a tagged release. It does not claim a tagged release or published
documentation.

## What was verified headlessly

Every acceptance test of the story runs offline: the listener on a loopback port the test binds,
the reads on the fake `connectors` of `loom-connectors`, the models recorded answers. They pass in
the unit's gate:

## Not verified here

- No A2A client other than the tests' raw HTTP/1.1 requests reached the listener. The wire is the
  proto JSON of A2A 1.0.1 as the `a2a` repository specifies it; that a third-party client reads it
  is unverified until the manual run.
- The conformance suite drives `loom.agent.AdmitA2aRequest` on its declared inputs alone; that the
  listener derives them from the request head is held by the tests above.
- Conformance checks the boolean decision tables of `AdmitA2aRequest` and `AdmitServe` only; the
  integration tests above hold the `admit()` wiring from the request head and the `SpecPlugin::new`
  and `agent serve` wiring of `admit_serve`.

## Manual run

No manual run was made: the implementation session had no cluster, no model credential and no
connection, and the story's tests use none. The record of one is pending. To make it:

1. Serve a spec with `expose.a2a` and its bearer: `LOOM_A2A_BEARER=<token> b10x-loom agent serve
   --spec <FILE> --state <DIR>`, or deploy it and `kubectl port-forward` the agent's port.
2. From a local Claude Code session with an A2A client configured with the URL
   `http://127.0.0.1:<port><expose.a2a.path>` and the bearer, ask a question the spec's sources
   answer.
3. Record here the card the client read, the task's id and final state, the proposal and the
   source the record names, and that the state directory holds no `approvals/` entry and the
   channel no message from the turn.
