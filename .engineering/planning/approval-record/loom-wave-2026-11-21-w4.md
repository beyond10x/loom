`story:boundary-admits-declared-http-egress` and `story:ess-format-31` both edit
`ess/domains/resource.yaml`; `story:confinement-opens-from-engine-config` and

`website/docs/reference/sdk-stability.md`. `story:boundary-admits-declared-http-egress`
(requester `ai-agent-platform`) and `story:agent-spec-constraints-in-crd` are not requests of
session `sdc` and are not in the wave.

Session `sdc` accepted two facts on the confinement story with the approval: a `local` run is not
kept for resume (`b10x-loom run` refuses `--confinement local` with `--state`, the command line's
usage refusal, exit 2), and `ChildResult.driver_record` becomes optional, a `**Breaking:**` line.

Order against the ESS toolchain move: Loom's release rule moves the `ess` pin to the newest ESS
release (0.86.0 to 0.96.0) in a release, and a release (0.58.0) is being prepared, held for the
operator's own word. Session `sdc` decided: the move goes first as a one-unit wave if it is pin
and regeneration only, and this wave goes first on 0.86.0 if the move needs hand changes or a
decision. A probe in the managed tree `loom-ess096-probe` (uncommitted) found that under 0.96.0
the Commission system's gate and conformance refuse `HoldSuspension` in three places. So this
wave runs first, on 0.86.0.
