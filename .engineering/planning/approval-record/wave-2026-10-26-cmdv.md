Decisions taken inside the item:

- D1. The units run one after another, stacked: each unit's branch forks from the wave head after
  the previous unit merged, since every pair collides on the files above and the disk allows one
  build at a time. Generated output and the CRD are regenerated in each unit, never merged by hand.
- D2. A `Command` resource renders a `batch/v1` Job (`backoffLimit: 0`, `restartPolicy: Never`, no
  `ttlSecondsAfterFinished`, so the finished Job stays readable) whose pod template is today's
  `Command` pod; an `AgentServe` resource keeps its Deployment. A new generation's Job replaces the
  old one; the controller never re-creates the Job of a generation whose run it saw finish.
- D3. The run-once lifecycle is declared in `loom.resource` first: states for a finished run
  (completed, failed), not terminal (a new generation respecifies), and a run observation command
  beside `ObserveDeployment`.
- D4. The exit code and end time come from the Job's pod
  (`status.containerStatuses[].state.terminated`), so the chart's Role gains read-only `get` and
  `list` on `pods` in the controller's namespace; it still grants nothing on Secrets or Events.
- D5. Admission refusals of the new spec members (`spec.env`, `spec.configFiles`) stay in
  `crates/loom-operator/src/admission.rs`, held by Rust tests, as every controller refusal is
  today; declaring the controller's refusals in ESS is `story:operator-constraints-in-ess`
  (proposed). The ESS-first change of u3 and u4 is the spec members the CRD is projected from.
- D6. Release after the wave per AGENTS.md § Releases, the version `release-check` accepts for the
  entry (0.44.0 when a `**Breaking:**` bullet or a new stable surface is there); the `ess` pin stays
  0.69.2, the newest ESS tag at the wave's opening.

Moves: u1-u4 draft -> proposed -> active at the opening, active -> implemented at the close.

The wave's commits, under the grant: the opening store commit, per unit its ESS-first commit,
implementation commits and adversary test commits, the merges into `wave/2026-10-26-cmdv`, the
review and closing store commits, the bot pull request, the fast-forward of `main`, then the
