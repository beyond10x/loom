## Decisions taken in planning

- D1: the domain is `loom.resource`, one domain beside `loom.agent` (design D8), holding the
  resource's spec type and the controller's lifecycle of it; the spec's `agent` member is
  `loom.agent.AgentSpec` itself (design D1).
- D2: the record keeps the generation it applied and the check's result, not the spec: a stored
  `AgentSpec` holds a `Decimal` no view can observe on ESS 0.69.0 (`ESS-SYNTH-001`), which would
  leave the refusal and preserving scenarios unwritten. Reported as an ESS gap; the spec stays in
  the cluster, which is where a controller reads it anyway.
- D3: the CRD file lives at `deploy/crd/loomagents.loom.beyond10x.dev.yaml`, generated by
  `loom-xtask crd-generate` and held by `task crd-drift` inside `task check`; the projection
  itself is a library function of the new crate `b10x-loom-resource`, so the controller (step 6)
  can embed the same bytes.
- D4: `ess/system.yaml` moves from `ess/24` to `ess/25`, the format the create-or-update branch
  needs; the ESS pin (0.69.0) does not move, this being no release.
- D5: no `loom_sdk` re-export and no SDK stability entry: the resource types are the controller's,
  which lives in this repository.
