**4. Findings** (all JUDGEMENT, all introduced by the pin)
- **`Cargo.lock:5217`**: `tempfile` 3.27.0 now resolves `getrandom` 0.3.4 instead of 0.4.3. No package changed version, but Substrate does not need this edge to move. Reached by every crate using `tempfile`. Harmless churn.
- **`crates/loom-intake-slice/Cargo.toml:31`**: `substrate-host` is pinned with default features. On 0.21.0 those include `kubernetes`, which pulls `b10x-substrate-kubernetes-client` into the operator's graph. That crate brings hyper, rustls with aws-lc-rs, tokio-rustls, and also `tokio-tungstenite` and `tungstenite` (`Cargo.lock:5349`, `:5551`), a WebSocket stack the story does not name. `cargo tree -i tokio-tungstenite` reaches `b10x-loom-operator`. Loom never calls any of it, and the story puts the kubernetes features out of scope.
  - Correction (named, not applied): `default-features = false, features = ["git"]`. After that, re-check the aws-lc-rs statement at `crates/loom-operator/src/main.rs:53`, which still holds at this commit through the kubernetes client.
- **`crates/loom-intake-slice/src/confinement.rs:2203`** (`OWNED_MOUNTS`, documented at `:1120-1123`): Substrate 0.21.0 also binds `/etc/alternatives` read-only into every confined run on hosts that have it (Substrate `crates/substrate-host/src/process.rs:2745-2749`).
  - That path is not in Loom's list of Substrate-owned mounts, so a read-only root at `/etc/alternatives` passes Loom's check and hides Substrate's bind.
  - The CHANGELOG's "no behaviour change" also misses that a confined child's view grows by this directory on Debian-family hosts.
  - The bind applies by default on such hosts. This host has no `/etc/alternatives`, and nothing I found configures that mount.
- **`crates/loom-intake-slice/src/confinement.rs:2828`**: the refusal of a request carrying `requires` is not measured by any test. The only case with such a request (`:3998-4005`) also has a record echoing it, and `:2829` refuses that on its own, so deleting `:2828` would leave the suite green. I could not add the missing case because `check_record` is private, and I did not build a mutated copy, so this is from reading the test, not a run.
  - Nothing reaches it today: Loom's request builders (`:1538`, `:3258`, and `session_input` through `:1501`) all send `None`.
  - Correction: add a unit case with `requires` in the request and `None` in the record.
