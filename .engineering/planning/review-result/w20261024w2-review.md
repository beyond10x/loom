## Findings

- Adversary, `story:b10x-text-deltas` (fixed in bcc84b98): b10x-harness retries a turn after a
  retriable wire failure and says so with `turn-retried`, which metaharness passes on as an opaque
  event. The executor ignored it, so the failed attempt's fragments were joined onto the retry's
  action line and no action line was read. The event now clears the current turn's text;
  `crates/loom-session-executor/tests/adversary_w20261024w2_u1.rs` holds the 10 cases.
- Adversary, `story:refused-selection-stays-refused` (no fault): the shipped
  `selection::select_action` refuses a held id in every state (Selected, Refused, Admitted,
  Overruled) ahead of every catalogue guard and leaves the row as it was; a fresh id after a
  refusal, a second confidence fallback and two Looms sharing a namespace still work.
  `crates/loom-executor/tests/adversary_w20261024w2_u3.rs` holds the 7 cases.
- Checked and not faulted: no production path reuses a selection id (each Loom gets a fresh
  namespace, `with_instance` is test-only); the overruled id cannot collide with a selection id;
  the pipeline's new `NoUsefulAction` return stays under Commission's idle bound.
- Left as is: `Loom::select` writes no record and accepts a reused id; refusing it would need a
  further `SelectionRefusal` variant.
