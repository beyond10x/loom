## 4. Findings

Base is `ecefe180`. Findings cover tree `5fc843fe` plus my untracked test file.

1. **CONFIRMED, warning:** `decode.rs:68` parses text up to `MAX_DOCUMENT_BYTES` (1 MiB) with `serde_yaml_ng`.
   - Time grows 4× per doubling of nesting, so quadratic. A 1 MiB run of `[` extrapolates to about an hour in a debug build, and my cases showed a 100,000-deep sequence (200 KB) and 262,144 `a: {` (1 MiB) not returning in 20 s.
   - Tests: `a_mebibyte_of_open_brackets…:213`, `a_hundred_thousand_deep…:221`, `a_quarter_mebibyte_of_open_braces…:235`.
   - Reach: any text passed to `decode`. Nothing in the workspace calls it yet, and operators write the documents.
   - Fix: cap flow or block depth before parsing, or lower the byte limit.
2. **CONFIRMED, note:** `decode.rs:68`, alias expansion.
   - The 1 MiB limit does not bound what is read: 8 KB of text expands 250-fold to 2M nodes and 350 MB. Roughly 100 MB of text would fit under the 1 MiB limit's expansion ceiling.
   - Test: `alias_expansion_is_bounded…:256`.
   - Reach: any text passed to `decode`. Nothing found beyond an operator's own file.
3. **CONFIRMED, warning:** a value spelled two ways is kept twice (`decode.rs:137`, `:152`, `:530`, `:693`, and `json()` at `:735`).
   - `key_text` (`:789`) turns the keys `0` and `"0"` into one name, and nothing checks the result for duplicates.
   - `results: {0: passed, "0": failed}` loads with two rows for value `0` (`:78`). The same holds for `retry_when` (`:85`) and `independence` (`:94`).
   - Reach: a hand-written table that mixes quoted and unquoted numeric keys. The guide's own example quotes `"0"`.
4. **CONFIRMED, warning:** `decode.rs:119` `registration()` accepts what the registry refuses.
   - `crates/loom-protocols/src/lib.rs:244` `parse_registration` requires a lowercase first letter, only lowercase letters, digits and hyphens, at most 100 bytes, and a positive canonical major. The decoder accepts `Story@1`, `story@0`, `story@01`, `1story@1`, `story_x@1` and `story.x@1`, an unbounded name, and a major that overflows u64.
   - Test: `:119`.
   - Reach: any `decode` call without a catalog. `check` then answers `ProtocolMismatch` instead of `InvalidProtocol`. The guide (line 16) says only `name@major`. The SDC protocol ids are dotted, so a converted file written `sdc.direction@1` decodes and then fails at load.
5. **CONFIRMED, note:** `decode.rs:753` `object()` accepts a tagged mapping.
   - `executor: !x {…}` decodes, so the tag is dropped silently. A tag on a scalar, a list or a key is refused (the first 7 positions in my test pass).
   - Test: `:181`.
   - Reach: a document with a tag on a mapping.
6. **CONFIRMED, note:** `decode.rs:733` `json()` keeps a `<<` merge key as a literal member.
   - `arguments: {<<: {a: 1}, b: 2}` yields members `["<<","b"]`. Merge is unsupported, so an author who expects it gets a member named `<<`.
   - Test: `:133`.
   - Reach: a document using a merge key in `arguments`.
7. **CONFIRMED, note, and the expectation is mine:** `decode.rs:690` / `load.rs:107` never check a `retry_when` kind against the protocol's evidence kinds.
   - `retry_when: {ess_gat: [failed]}` loads and can never fire.
   - The story does not list this check. The guide's own example uses a kind from another action, so only "declared in the protocol" can be required.
   - Test: `:142`.
   - Reach: a typo in `retry_when`.
8. **CONFIRMED, note:** `decode.rs:793` contradicts its own comment at `:788`, "spelled as written".
   - Keys `1.50` and `True` come back as `"1.5"` and `"true"`. Only `007` survives.
   - Test: `:71`.
   - Reach: unquoted numeric or boolean result keys. Same cause as 3.

JUDGEMENT, no test, all introduced, nothing found that reaches them:
- `decode.rs:492-517` and `load.rs`: nothing ties the evidence source to the executor kind.
  - `from: effect` on a `program`, or `exit` or a pointer on an `agent`, `person`, `open` or `copy`, is accepted.
  - The story defines `effect` only for open, agent and person.
- `load.rs:156-163` checks workspace paths for `artifacts`, `inputs` and `outputs` only. `executor.bindings` (the child's file) may be `/etc/x` or `../x`.
  - The story does not list it, and the guide does not say what the path is relative to.
- Guide `bindings.md:149-150` says a `copy` "names the evidence `kind`", while the code member is `executor.evidence` (the example at line 139 is right).
  - The story says "an evidence `kind`". A reader following the prose writes `kind:` twice in the executor, and the duplicate-key refusal answers `Malformed` without saying why.

- A list for `actions` is implied by "refuses a duplicate action". An object `{kind: …}` for `executor` and `Report` with a `pointer` for a `/pointer` match the story's wording.
- A null result is stated in the ESS comment and in the guide (line 158).
