Reviewed and found nothing wrong:
- `track.requests.last_mut()` always points at this step's request, because it is pushed right after `revalidate`.
- A stale step leaves `granted`, `pending` and `verdict` unused, and the next iteration judges the move (runtime.rs:1243).
- Run loop after the re-read: before invoke there are only `effects.performs`, the trial-budget check and in-memory pushes. Commission does no I/O there, so I wrote no case.
- Things a refused resume leaves behind: an approval the provider consumed inside `decide` (Mandate) stays consumed. The Suspension stays `Pending` at a revision the case has left, so every later resume is refused, and `run_with_suspension` starts no new Run while it is held. That fails toward less authority. The same state already followed the base's first `CaseMoved` check, so it is a liveness question, not a security one. I read this in the code and did not test it.
