## Findings

- Adversary (fixed in 2450a32b): a b10x-harness endpoint with an empty `token_file` and no
  `api_key_secret` launched the loop with `--oauth-token-file ""`, pointing it at no credential.
  `check_api_key_secret` now refuses it before the copy, naming both missing credentials. The
  `api_key_secret` doc no longer calls `--credentials` a loop flag.
- Security (fixed in faeb5b0e): a name holding a NUL byte passed
  `metaharness_b10x::validate_api_key_secret`, so the copy was made and the launch planned with an
  argument no exec can carry. Any control character, a newline included, is now refused before the
  copy, the name quoted escaped. The AGENTS.md § Session executor paragraph, inserted
  mid-sentence, now follows the sentence it split.
- Checked and not faulted: the key value never enters Loom, metaharness, argv or the child's
  environment; a name starting with `-` is attached as `--api-key-secret=<name>`; no caller key
  variable reaches the child on the secret route; the subscription route is unchanged.
