- Reword :724–726 and :1100 so they promise only the variables named.

**5. Attacked and could not break**
- **Name spelling:** lowercase or space-padded names, and names starting with `_`, are refused by Substrate before anything runs (`process.rs:3131-3146`). An empty value is refused by `contains_key`. A name can't appear twice (`BTreeMap`).
- **`OPENSSL_CONF`:** I tried pointing OpenSSL's config at a different CA file with curl 8.22 / OpenSSL 3.6.4 and Python 3.14 `ssl`. Neither redirected (probe.log). `XDG_CONFIG_HOME` has no effect on curl (probe2.log).
- **Private copy:**
  - It sits at `$TMPDIR/loom-substrate-*/ca-bundle.pem`: directory 0700, file 0400 created new, owned by the process, and outside every sandbox bind.
  - Each driver gets a fresh temp directory, so names never collide.
  - It is removed when `open()` refuses after writing it, and when the runner drops.
  - No `loom-substrate-*` directories were left after the suite.
  - One copy and driver per distinct path and bytes is kept for the runner's lifetime. That is by design, per the ruling.
- **Changed bytes between launches:** the second launch gets a new driver, or `CapabilityUnserved` while the first is still running (documented).
- **The read:**
  - A link as the last component, `/proc/self/fd/N`, a FIFO, a device and a socket are all refused. A FIFO swapped in after the path check is caught by the check on the open file.
  - The "grew past 1 MiB while read" branch has no test, and I couldn't build the race deterministically.
  - A link in a parent directory is followed. That matches doc step 4 ("its last component not followed"). The `with_ca_bundle` wording "an open that follows no symbolic link" is loose; I'm noting it, not rating it.
- **1 MiB ceiling:** exactly 1 MiB is accepted and one byte over is refused, the same limit as Substrate's (`transport.rs:686`, `hosted.rs:238`). An empty file after a non-empty one is refused.
- **Leaks:**
  - The bundle's debug output shows the path, length and sha256, never the bytes.
  - The drivers list prints only its keys, and refusals name only the host's path.
  - The digest hashes the path and sha256.
  - Neither the bytes nor the private path appear in any error, log or applied record I could find.
- **`libc`:** no `unsafe` (`lib.rs:1` forbids it), and every file descriptor is closed on each error path.
