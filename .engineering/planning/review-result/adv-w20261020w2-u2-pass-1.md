- **What was measured:** `adversary_w20261020w2_u2.rs:231`, exit 101. The budgeted control in the same test passes.
- **Why it matters:**
  - Every other path puts completion first: `derive` rule 1, runtime item 0 (loads the case after a `Performed` effect) and item 2.
  - This unit's own ESS comment says `IdleBound` ends a run only "where it would otherwise go on".
  - The idle guard returns without loading the case.
  - On the other side, runtime.rs:155-158 counts a repeated admission idle "whatever the effect port answered", so changing this is a design call.
- **Origin:** I read 18cb4e6 with `git show` and did not run it there. Its guard at runtime.rs:1293 ends this same run `NoAdmissibleAction`. The ordering is old; this unit only gave the wrong outcome a name.
- **What reaches it:** an SDK host whose `LoopContext::step_budget` is `None` and that sets no run-budget `max_steps`. That is a documented setup (runtime.rs:9) and the host the story is written for. No caller in this repo uses it: slice run.rs:1082, plugin turn.rs:476 and the SDK example software_change.rs:298 all set a budget.
- **Fix to name, not applied:** when this iteration's effect was `Performed`, load the case and check completion before the idle bound ends the run, as item 0 does for the budget, and amend runtime.rs:155-161.
