## Findings

- confinement-spec, adversary and security (fixed in d0c27423): `ChildCommand::confined` applied
  the environment and the network of every spec, so a spec naming nothing wiped an environment
  the command already had and set its network back to none beside its apertures, against the
  documented "a spec naming nothing leaves the command as it was". It now applies the environment
  only when the spec names a variable and the network only when it is not `None`.
- session-lineage, adversary (fixed in 85b669d6): a host handing out the predecessor's own id got
  a session recorded as continuing itself, its row overwriting the predecessor's; ids 1, 2, 1 gave
  one executor a lineage that loops; one commission written in capitals was refused as another. A
  call's session id equal to the predecessor's or to one already recorded now suspends the step
  with `ExternalAvailability` naming it, and commissions are compared as parsed UUIDs.
- pinned-consumers-agency-shape, adversary (fixed in 7a0fc675): the consumer's clock was frozen at
  2026-01-01, so a spec deadline already past was read as ahead and the run ended `IdleBound 3`.
  `agency::run` now takes its clock from the caller (`SystemNow`, `FixedNow`).
- loop-context-split, adversary: nothing red. A parts context left at its defaults answers as a
  plain `LoopContext` does, and the consumer shapes tried (a boxed context, a generic wrapper, a
  type with its own impl) still compile and run.

## Notes not made into tests

- The SDK's new `Clock` trait shares its name with the slice's `clock::Clock`; the name the story
  uses was kept (approval-record D5).
- `SystemNow`'s reading of the system clock is not tested; the tests run at fixed instants.
- `crates/loom-xtask/tests/pinned_consumer.rs` checks the agent consumer's dependencies, not that
  its clock comes from the caller.
