**4. Findings**

1. **CONFIRMED, warning.** `crates/loom-executor/src/selection.rs:296`. An action stays useful while any kind it may produce is open. In `software-change@1`, `tests.run` may produce both `test_result` and `regression_test_result`.
   - A run without a regression test command never submits `regression_test_result` (`crates/loom-cli/tests/slice_run.rs:1442-1444`).
   - So with `tests.pass` true, `tests.run` is chosen at every step. Because a read sorts before every write, `implementation.edit` is never reached.
   - What reaches it: Loom's bundled protocol with any feature or refactor change, under the selector this unit makes public. No host wires the selector to it yet.
   - This is the story's own rule, so it is not something to fix in code alone. Possible changes to the story: count an action as done once it was performed at the current case revision and produced something, or treat only kinds some match reads as open.
2. **CONFIRMED, note.** `crates/loom-governor/src/lib.rs:1963`. `evidence_matches` skips order forms, so a kind only order forms read counts only records bound to the current revision. Canon's order forms read every accepted record.
   - After the subject moves, Canon's claim stays true but the kind reopens. The selector then picks the done action again, once per revision.
   - What reaches it: in `software-change@1`, `regression_test_result` and `implementation_change` are read only by `first` / `before`. Today the effect there is hidden by finding 1.
   - Fix: count a record of a kind read only by order forms whatever its binding.
3. **INFEASIBLE, note.** `crates/loom-executor/src/selection.rs:141`. The case check lives in the provided method `resolve_for_case`. A host type that wraps a `DeterministicSelector` and forwards only `select` gets the default, which drops the case, so the facts are read for the selector's own case.
   - A host cannot implement `ActionSelector` for `&DeterministicSelector` (Rust's orphan rule), so keeping access to the selector means writing exactly such a wrapper.
   - What reaches it: nothing found. The in-tree wrapper of this shape, `Recording` at `crates/loom-intake-slice/src/run.rs:1378`, wraps a `ModelSelector`.
   - Fix: say in the trait docs that a wrapper must forward `resolve_for_case`, or move the check out of the overridable method.

**5. What I attacked and could not break**
- **The three rules for a kind a claim reads:** binding, freshness at the exact `max_age` second, a fractional instant, no `observed_at`, no instant, an observation after the instant, invalidation, and a record about another artifact. All 108 combinations agree with Canon.
- **Divergence 2 (an invalidated record counts nowhere):** Canon lists it as invalidated under a claim only when a match that claim reaches reads it. Producing it again with the current upstream revision closes the kind, so it repeats only while a producer keeps recording a non-current upstream revision. I found no protocol shape that does that.
- **Existing selectors through `resolve_for_case`:** the default delegates to `resolve`, once. `HybridSelector` hands the case to both selectors. `Loom::select` still names no case.
