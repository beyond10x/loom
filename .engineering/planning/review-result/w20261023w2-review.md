## Findings

- several-egress-apertures, adversary (fixed in ca8fea18): a later aperture naming its host in a
  hex `inet_aton` form (`0x7f000001`, `0x7f.0x1`, `0x7f.0.0.0x1`, `0x0a000002`) passed every
  check before launch; glibc resolves it as an address, and live the child reached the first
  aperture's destination. Every numeric host (decimal, hex or octal labels) is now refused on
  apertures 2 to 4, and on the first only `127.0.0.1` is accepted, which also closes the
  pre-existing first-aperture gap (`0x0a000001` accepted while `10.0.0.1` was refused).
- several-egress-apertures, security (fixed in b5386650 and ca8fea18): an unconfined run recorded
  `network: []`, which the specification reads as no network, where 0.36.0 recorded
  `unconfined`. `network` is now optional; absent is an unconfined run. Two refusals did not name
  what AGENTS.md said they name; they do now, and the `run_child` comment names the set.
- child-workdir, adversary (fixed in 53963412): a workdir without search permission passed every
  check before launch, and live bubblewrap's chdir failure came back as the child's own exit 1.
  It is now refused before launch, a run whose output carries bubblewrap's chdir diagnostic for
  its workdir is refused, and a workdir holding a control character is refused escaped.

## Notes not made into tests

- A workdir directory swapped between Loom's check and the launch is refused by Substrate's walk
  but comes back as `CapabilityUnserved`; AGENTS.md names it.
- The post-run chdir refusal is held by a unit test only; no live path to it was found without
  racing a permission change.
- `/workspace/.git` is accepted as a workdir; it stays read-only unless the host names it
  writable.
