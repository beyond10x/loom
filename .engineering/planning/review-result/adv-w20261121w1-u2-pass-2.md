## 4. Findings

Tree `e991251b` plus my untracked file.

1. **CONFIRMED, warning:** `tree.rs:112` makes `bounded` count text, not structure, so it refuses valid YAML.
   - The `open` counter is netted across lines and counts brackets inside block scalars, so 62 lines of unclosed `{` in one block scalar are refused.
   - Test: `…headers_with_unclosed_braces…:208`.
   - Smallest realistic text refused wrongly: a `handoff` or `prompt` block scalar listing 62 function headers whose bodies are elided, such as `func handlerN(w http.ResponseWriter) {`. The YAML is valid.
   - What the author has to do: close the braces or move the listing out of the document. Quoting does not help, because quoted text is counted too.
   - The implementor listed this as a residual, but the 62-line threshold is a plausible agent-prompt shape.
2. **CONFIRMED, warning:** `tree.rs:103` counts brackets in comment lines, so 63 comment lines with an open `[` are refused: `# note 1 [see`, and so on. Comments are not data.
   - Test: `…comment_lines_with_an_open_bracket…:217`.
   - Reach: an SDC file annotated with comments.
3. **CONFIRMED, note:** `tree.rs:88` counts indentation inside a block scalar as nesting. A text line indented 140 spaces (an aligned table or diagram) is refused, though it is content.
   - Test: `…indentation_inside_a_block_scalar_is_text:229`.
   - Reach: pasted diagrams in prompts. It needs about 130 columns, so it is rare.
4. **CONFIRMED, warning:** `tree.rs:216` `visit_str` copies the scalar on every alias use, and the node count bounds values, not bytes.
   - One 100 KB scalar used 800 times is 82 MB of strings from a 103 KB document. A 1 MiB document (500 KB scalar, 100,000 uses) extrapolates to about 50 GB, which I did not run.
   - Test: `an_alias_to_a_large_scalar_is_bounded_in_bytes:138`.
   - Reach: any text given to `decode`. Operators write the documents and nothing in the workspace calls `decode` yet.
   - Fix: count the bytes of expanded scalars, as the nodes are counted.
5. **CONFIRMED, warning:** `decode.rs:725` is a regression against the pass-1 head: the reader's `Node::Real` is written with `f64` Display, so a float in the literal `arguments` loses its fraction.
   - `1.0` becomes `1`, `1e3` becomes `1000`, `-0.0` becomes `-0`. At `5fc843fe` `serde_yaml_ng` wrote `1.0` (ryu), as `number.rs:308` shows.
   - Test: `a_float_written_with_a_fraction_stays_a_float…:82`.
   - Reach: any literal `arguments` with a float such as `{temperature: 1.0}`. A program or agent that checks for a float sees an integer.
6. **CONFIRMED, warning:** `tree.rs:72` and `decode.rs:68` refuse a file that starts with a UTF-8 byte order mark, with the message "more than one document is not supported".
   - Test: `a_leading_byte_order_mark_does_not_refuse_the_file:94`.
   - Reach: a file saved by an editor on Windows, then read with `read_to_string`. This is valid YAML text.
   - Fix: strip a leading U+FEFF before parsing.

JUDGEMENT (no failing case), all introduced:
- **`1` and `01`:** both are kept as written, so the result table holds the rows `("1", a)` and `("01", b)`. Status 1 matches only the first; whether `01` can ever match is up to the consumer (`story:bound-program-result-table`). The same holds for `0.0`, `0x0`, `00` and `+0`. Nothing reaches it today.
- **The `!!` residual: no check bypass found.**
  - `!!str 30` as `timeout_seconds` is refused.
  - `!!int "8"` as `timeout_seconds` or `max_runs` loads as 8, which is correct YAML.
  - `!!binary` stays base64 text, `!!set` and `!!omap` read as a mapping and a list, and `!!null x`, `!!float 3` and `!!bool "true"` for a number member are refused.
  - A standard tag on a key loads (`!!str 0`, `&a x`).
  - The guide (`bindings.md:177`) says "a tag such as `!x`" is refused, which is true only for non-standard tags.
- **Key error text:** a sequence or mapping key is refused with "expected a YAML tag starting with '!'". The text is misleading but the refusal holds.
- **The path base:** `load.rs:201` and the guide say `executor.bindings` is relative to the workspace root, whereas the SDC's old files used `{dir}` (the bindings file's own directory).
  - `.`, `./`, `a/`, `~/x` and `a\b` are accepted; absolute, `..` and empty are refused.
  - A child bindings file next to the operator's bindings file but outside a case's workspace cannot be named.
- **Indent-4 JSON:** by reading, a JSON file pretty-printed with a 4-space indent counts three levels per real level (indent, open bracket), so it hits the cap at about 21 real levels. This is as the guide describes the counting, and no realistic file reaches it.
