**4. Finding** (covers ccac1f32)

| file:line | Finding | Verdict | Origin | Severity |
|---|---|---|---|---|
| `crates/loom-plugin/src/turn.rs:295` | A model that answers without the forced call is turned into `PluginError::Unavailable`. The host then never records that item, never saves the cursors, and never handles any item after it in the poll. | NEEDS-CHANGE | introduced | blocker |

- **What was measured:** assertions at `adversary_w20261020w4_u3.rs:162` and `:242`, exit 101.
- **How it is reached:**
  - Item text the provider refuses. llm 0.8.1 decodes a Messages `refusal` stop as `Incomplete{reason:"refusal"}` (`llm-messages/tests/streaming.rs:725-730`), and a Responses `content_filter` the same way.
  - `model_selector.rs` `answer` then returns "the model did not call" → `SelectorError::Unavailable` → Loom outage → `turn.rs:295` → `lib.rs:515-519`, which ends the cycle with no cursor save. Each cycle spends one more model request.
  - A text-only `EndTurn` answer reaches the same branch through `validate_for`.
  - In production this is `b10x-loom plugin run` → the Slack plugin's default turn.
- **Why `introduced`:** at the base, the same answer took this path: `Incomplete` → `LoopStop::ProviderIncomplete` (`harness/turn_loop/mod.rs:663`) → `NoUsefulAction` (`harness/governed.rs:581`) → `stopped`. The diff does not touch either file. I did not run the case at the base: there is no base tree, and `TurnModel` changed type, so the case does not compile there.
- **Fix (named, not applied):** separate "the model answered unusably" from "the model could not be reached". For example, `TurnBriefing` overrides `Briefing::select`/`arguments` to note that the model answered without the call, and `turn()` ends that Run `stopped` (or returns `PluginError::Turn`, counted against the item).

**5. What I attacked and could not break**
- **Tags in the data block:** I tried item text, item id, describe schema, a read answer containing `</earlier-steps>`, `&lt;` forms, CDATA, nested and double-escaped `\u003c`. `<`, `>` and `&` are escaped everywhere, so no literal tag appears. Full-width look-alike brackets (U+FF1C/U+FF1E) pass through unescaped, but only inside JSON strings, so I did not raise them.
- **Raw newlines:** describe `operation`/`schema`/`revision` and item id/revision get only `<>&` escaping inside backticks. The base also printed them raw, and I found no source that supplies such a value, so not raised.
- **Order and duplication:** one transcript entry per effect, in order. The selection and argument requests of one step see the same transcript.
- **Budget:** `Lent` counts every retry attempt. Its `ErrorCode::Refused` is never retried (`may_retry`). Each request gets at most 3 attempts. When the step budget and model budget run out together (8 steps × 2 = 16 requests), the detail names the model budget; the base had the same coincidence at 8/8.
- **Governance:** a selection outside the candidates is `NotInCatalogue` before any argument request, and it is revalidated against the governor. `DataSourceEffects` is unchanged, so `reply.propose` still writes only the record.
- **The move:** the slice's request builder, retries and JSON error mapping behave the same as before. `model_selector` has no slice dependency. `git grep -nE 'harness::|LlmModelPort' crates/loom-plugin crates/loom-cli/src/plugin.rs` prints nothing (exit 1).
