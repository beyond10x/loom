**4. Findings**

1. **INFEASIBLE, warning.** `crates/loom-governor/src/lib.rs:1862-1868` (`counted_kinds`). A record counts if it is about its own subject's current revision, and the result is collected per kind only. So a record of kind K about any declared artifact closes K for every action, even when no evidence match reads that record. Acceptance bullet 1 fails in its own words (red at :192), and the selector stalls with the needed action admissible (red at :218).
   - What reaches it: a protocol that reads one kind about two subjects, or a producer recording a kind about an artifact no match reads it for. Nothing found: in the 3 Loom protocols and 8 SDC protocols every kind is read about exactly one subject.
   - Fix: count a record only when some evidence match in the IR (claims, preconditions, outcomes) reads it by kind and by subject (no subject on the match, or the same subject); keep the fallback for kinds nothing reads.
2. **INFEASIBLE, warning.** `crates/loom-governor/src/lib.rs:1848-1868`. When no claim lists a kind's exclusions, the governor falls back to checking the subject revision only. That fallback ignores `max_age`, so an expired record of a kind read only by a precondition or outcome counts as present while Canon sets it aside (red at :290).
   - What reaches it: nothing found. No shipped protocol reads evidence directly in a precondition or outcome. The only `max_age` kind in a shipped protocol (`health_observation`, `sdc-release.protocol.yaml:37`) is read by a claim with a subject, so its exclusions are listed.
   - Fix: apply the kind's `max_age` at the trusted time in the fallback.
3. **INFEASIBLE, note.** `crates/loom-executor/src/selection.rs:288`. The selector is built for one case. `Loom::run` with another case's commission silently reads the bound case's facts. `CaseFacts` (:176) names no case, so nothing can check the mismatch (red at :250).
   - What reaches it: nothing found. `story:tree-run-command`, the first host, does not exist yet.
   - Fix: put the case in `CaseFacts` and have Loom refuse a mismatch, or document one selector per case.

**5. What I attacked and could not break**
- Safety: the selector only ever returns an `Admissible` candidate, whatever the ports answer.
- Determinism: nothing iterates a hash map or reads a clock. Ordering is (write, id) through `min`, where id order is byte order (the code comment says "code point"; the story names no order). Ties happen only between identical ids.
- `may_produce` and the "facts do not name it" rule: with `CanonGovernor` every IR action is named and the frontier comes from the same IR, so neither can cause a wrong `NothingAdmissible`.
- Step history: a due write waits only while some read stays useful. The only multi-kind action in the shipped protocols is `sdc-intake` `questions.check`, which may produce both `questions_shape` and `questions_settled`. If one of them is never produced, that read repeats and starves due writes, by the story's own rule.
- Codec (`codec.rs:93,143`): round-trips correctly and an unknown name gives `None`. I checked this by reading only; my brief allows no test file in loom-conformance.
- Existing behaviour: `FirstAdmissibleSelector` is unchanged, no existing test file changed, `FrontierAction` and `CatalogueEntry` gained no member, and nothing under `ess/commission/` or `generated/rust/commission/` changed.
