## Question

Is wave 2026-10-14-w1 (ordered evidence, Mandate authority and the consumer foundation) approved,
and how is it built?

## Units

U1 story:change-evidence-order: the slice submits `implementation_change`, a bugfix's
`regression_test_result`, `observed_at` and the trusted `producer`, and its governor evaluates at
the host instant, so `red_first.required` can be discharged. Surfaces: `crates/loom-intake-slice`,
`crates/loom-governor/src/lib.rs`, `crates/loom-cli`, `ess/intake/`, `generated/rust/intake/`.
Adversary and security review: it changes what a governed bugfix admits as done.

U2 story:mandate-authority: a new crate `b10x-loom-mandate` answers Commission's authority port
with Mandate v0.9.0. Surfaces: `crates/loom-mandate`, `ess/domains/authority.yaml`,
`generated/rust/loom/`, `Cargo.toml`, `Cargo.lock`, the Commission dependency guard. Adversary and
security review: it is an authority provider.

U3 story:mandate-approval-on-resume: `approve` writes the Mandate approval, `resume` consumes it.
Starts after U1 and U2 merge: it depends on U2's crate and shares `ess/intake/domains/routing.yaml`
and `crates/loom-intake-slice/src/intent.rs` with U1.

U4 story:pinned-consumer-check: an external crate builds the documented embedding in `task check`.
Surfaces: `consumers/pinned/`, `crates/loom-xtask/tests/pinned_consumer.rs`, `Taskfile.yml`.

U5 story:harness-migration-guide: the Harness-to-Loom guide with a compile check of each path it
names. Surfaces: `website/docs/guides/move-to-loom.md`, `crates/loom-sdk/tests/harness_paths.rs`,
`crates/loom-executor/tests/harness_map.rs`.

U6 story:command-event-contract: a committed snapshot of the run-events records, checked by
`task docs-check`. Surfaces: `docs/contracts/`, `crates/loom-docs`.

U7 story:sdk-host-port-stability: the stable `loom_sdk` surface and a test implementing each host
port through it. Surfaces: `website/docs/reference/sdk-stability.md`, `crates/loom-sdk`. Starts
when a sub-agent slot frees (six at once).

The units share only prose every unit updates (AGENTS.md, README, CHANGELOG,
`website/data/status.json`, `website/docs/guides/embed-the-runtime.md` for U4 and U7); the
integration branch merges them one after the other. Not in the wave:
story:release-names-embedder-breaks (depends on U4, U6, U7); the drafts that wait on an ESS
release, Connectors or Substrate.

## Build

About 9G of target per unit that builds the workspace's dependencies, less for U6, and 16G for
the one full gate on the integration head, each reserved through the host's build ledger. Package
gates of the touched crates in each unit; one full gate on the final head, then one push and one
pull request; release 0.21.0 on merge.

## Decision (2026-10-14)

Approved up front, as one wave with one integration branch and one pull request; release on merge
through the repository's process. Widened the same day to every ready unit with disjoint scope. The
designs are the stories' Decision sections.
